# Проблемы работы с данными

## Проблемы и решения

| Проблема | Что сделать |
| --- | --- |
| Данные в общих папках доступны без ограничений по обязанностям. ФИО есть даже в названиях папок. | Разделить доступ: ресепшен — записи, врач — карты своих пациентов, кассир — платежи. Вместо ФИО в путях использовать ID. |
| Нет журнала действий и контроля передачи данных. Утечку сложно обнаружить. | Записывать чтение, изменение и выгрузку; учитывать источник и получателя; уведомлять IT о массовом скачивании. |
| Анкета содержит много сведений без указанной цели каждого поля. | Собирать только необходимое, медицинскую часть отделить от регистрации. |
| Не описаны основания обработки, сроки хранения, удаление и шифрование. | Установить правила хранения и удаления, обрабатывать запросы пациентов, проверить и включить шифрование. |
| Один сервер; резервное копирование не описано. Платежи дублируются в Excel и 1С. | Делать защищённые резервные копии, проверять восстановление; вести единый учёт платежей. |
| Для будущих API не определены ограничения доступа. | Проверять владельца данных; лаборатории передавать только необходимое для исследования. |
| Для будущей аналитики не предусмотрено обезличивание. | Удалять личные сведения и проверять, нельзя ли узнать человека по оставшимся данным. |
| Нет описанной классификации данных. | Назначать теги и сохранять ограничения при копировании. |

## Данные для защиты

| Данные и теги на диаграммах | Способ защиты |
| --- | --- |
| ФИО, дата рождения, контакты, адрес, договоры — `PII` | Шифрование, ограничение доступа, маскирование контактов при показе. |
| Заболевания, заключения, анализы, медицинские сканы — `PII`, `HEALTH`, `MEDICAL_SECRET` | Шифрование, доступ лечащему врачу и пациенту, обезличивание для аналитики. |
| Записи на приём — `PII`, `MEDICAL_SECRET` | Доступ ресепшену, назначенному врачу и пациенту; напоминания без диагноза. |
| Платежи — `PII`, `FINANCE`; при раскрытии обращения — `MEDICAL_SECRET` | Шифрование, доступ кассиру и бухгалтеру, исключение медицинских подробностей. |
| Кадровые сведения и зарплата — `PII`, `HR`, `FINANCE` | Шифрование, доступ уполномоченному бухгалтеру. |
| Складские сведения — `INTERNAL`; журнал действий — `AUDIT`, `INTERNAL` | Ограничение доступа; защита журнала от изменения, без содержимого медкарт. |

Также нужно проверить копии, почтовые вложения и выгрузки. Маскирование скрывает часть значения. Обезличивание исключает определение человека; одной замены ФИО на ID недостаточно.

## Тегирование и инструменты

1. В **OpenMetadata** зарегистрировать файлы и поля: владелец, срок хранения, теги из таблицы. Сканы тегировать целиком.
2. При копировании наследовать теги и сохранять связь с источником. `DEIDENTIFIED` («обезличено») назначать после проверки обезличивания.
3. По тегам применять ограничения в правах папок, 1С и будущих API. Каталог сам доступ не блокирует. Проверять, что пациент не получает чужие данные, а выгрузки не содержат запрещённых полей.

Инструменты: группы AD и права 1С — доступ; BitLocker — шифрование дисков; HTTPS/TLS — передача в новых API; Windows Audit и журнал 1С — аудит; Victoria Metrics — оповещения. Для OLE ограничить узлы и учётные записи: сам OLE не шифрует данные.

# Защита данных при хранении и передаче

Ниже - предлагаемые меры для текущих файлов и 1С, а также новых порталов и аналитики.

## Классификация и защита

| Данные и класс | Зачем защищать, риск | При хранении (at rest) | При передаче (in transit) |
| --- | --- | --- | --- |
| Медкарты, диагнозы, анализы, сканы - медицинская тайна | Раскрытие здоровья пациента. **Критический** | BitLocker; доступ только уполномоченным сотрудникам и пациенту к своим данным. | SMB 3 с шифрованием для файлов; TLS 1.2/1.3 для будущих API. |
| ФИО, контакты, договоры, записи на приём - персональные данные | Утечка личности и факта обращения. **Высокий** | BitLocker; разграничение прав; маскирование контактов в списках. | HTTPS/TLS для порталов; SMB 3 с шифрованием для Excel и сканов. |
| Платежи, кадры, зарплата - финансовые и персональные данные | Утечка доходов, подмена расчётов. **Высокий** | BitLocker на томах 1С; отдельные роли кассира и бухгалтера. | Шифрование SMB 3 для файловой 1С; для ККМ/OLE - меры ниже*. |
| Остатки ТМЦ и закупки - внутренние данные | Разглашение закупок, искажение учёта. **Средний** | BitLocker; права склада и бухгалтерии. | Шифрование SMB 3; для обмена OLE - меры ниже*. |
| Выгрузки для аналитики - класс источника до обезличивания | Повторное определение пациента. **Высокий** до проверки обезличивания | BitLocker; закрытая подготовка данных; аналитику - только проверенные сводные отчёты. | TLS; исходные данные передавать только в закрытую зону подготовки. |
| Резервные копии - класс самых чувствительных данных внутри | Утечка сразу большого объёма данных. **Вплоть до критического** | Restic: шифрование копий AES-256; ключ хранить отдельно. | TLS при сетевом копировании; сами копии также остаются зашифрованными. |
| Журналы действий - служебные данные, возможны ID пользователей | Подмена следов действий, утечка идентификаторов. **Высокий** | BitLocker; ограничение изменения журналов; без содержимого медкарт. | TLS; в метриках и оповещениях - только необходимые технические сведения. |
| Ключи шифрования и служебные токены - секреты | Получение доступа ко всем защищённым данным. **Критический** | Vault: защищённое хранение, права и смена ключей; средства восстановления - отдельно от данных. | TLS; исключить секреты из логов и обычных файлов конфигурации. |

*OLE сам не шифрует данные. Проверить поддержку защищённого обмена ККМ и 1С. Если TLS недоступен - использовать IPsec между совместимыми узлами или шлюзами; участок до ККМ изолировать и разрешить только необходимые соединения.

## Автоматический контроль

Планировщик Windows и PowerShell проверяют состояние BitLocker, шифрование SMB, настройки TLS и сроки сертификатов. Проверки API перед выпуском выявляют передачу запрещённых полей и доступ к чужим данным. Restic проверяет целостность копий; по расписанию выполняется пробное восстановление. Метрики ошибок и массовых выгрузок передаются в Victoria Metrics/vmalert для оповещения IT. Значения персональных данных и ключи в метрики не включаются.

## Реестр средств защиты

| Тип | Средство | Назначение |
| --- | --- | --- |
| ПО | BitLocker | Шифрование дисков серверов и рабочих ПК, где сохраняются защищаемые данные. |
| ПО | Windows Server: SMB 3, IIS/Schannel, IPsec | Шифрование файлового обмена, HTTPS и защита совместимых сетевых соединений. |
| ПО | Restic | Шифрование резервных копий и проверка их целостности. |
| ПО | Vault | Хранение служебных секретов и ключей, контроль их использования. |
| ПО | Планировщик Windows, PowerShell и проверки API | Автоматическая проверка настроек защиты и доступа. |
| ПО | Windows Audit, журнал 1С, Victoria Metrics/vmalert | Учёт действий, контроль показателей и оповещения IT. |
| Оборудование | TPM 2.0 серверов и ПК | Защита ключей BitLocker. |
| Оборудование | Отдельный носитель для зашифрованных копий | Хранение резервной копии отдельно от основного сервера с ограниченным физическим доступом. |
